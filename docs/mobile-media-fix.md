# 手机媒体加载与播放修复（2026-11-21）

## 已确认的问题

- 6 段 `core-workflow/ai-motion*.mp4` 为 4K、10-bit HEVC，部分码率高达约 27 Mbps（容器最高约 48 Mbps）。
- 22 段视频的 moov 索引位于 mdat 后，包括上述 HEVC、关键帧短片、部分机器人教程及牛肉汤饭。慢网络要额外请求文件尾部才能开始播放。
- 原播放器依赖弹窗挂载后的带声自动播放；iOS / 内置浏览器可能要求真实用户手势。参考：https://webkit.org/blog/6784/new-video-policies-for-ios/ 。
- 移动端预览仍使用 video poster，每个视频节点会独立处理加载；手机展示图也仍与电脑共用大尺寸版本。

## 处理

- 保留桌面文件与原素材，新增 32 个 `.mobile.mp4`。全部 H.264 8-bit yuv420p / AAC、moov 前置，转码版本长边不超过 960px，峰值视频码率 900 kbps；原本低于 800 kbps 的 10 个 H.264 文件只无损重封装。
- 手机视频合计 429.8 MB → 156.9 MB。完整时长与音轨保留，最大容器时长差 0.01 秒。
- 206 个手机图片版本（含封面）32.5 MB → 8.1 MB；宽度最多 720px，长图保持纵横比例。
- 手机视频预览改为懒加载静态图片，不挂载预览视频；图片按手机映射选择，电脑映射不变。
- 所有项目实际播放器共用 VideoPlayer：手机点击后在真实 click 事件内调用 play，保留原生控制条；显示缓冲、失败、超时重试和单独打开视频入口。
- 下方软件卡片和品牌备用画廊图片补充 lazy / async。

完整文件明细见 mobile-videos.json 和 mobile-images.json。导出脚本：scripts/prepare-mobile-media.py，参数为 ffmpeg 可执行文件，需 Pillow。

## 验证

- 构建与 TypeScript 检查通过；247 条项目资源路径及两个新增映射全部存在。
- 32 段手机视频完整解码通过；每段均确认 H.264 / yuv420p、moov 位于 mdat 前、时长差小于 0.12 秒。
- 手机视口检查硬件产品视频、机器人教程与竖屏美食播放器的来源、点击播放、进度及封面。
- 模拟视频第一次请求返回 HTTP 503：显示失败提示、重试与单独打开入口；点击重新加载后 readyState=4，播放进度继续前进。
- 这些检查不能替代用户真实手机在国内网络下的表现；GitHub Pages 的访问线路仍可能影响传输速度。未据此保证所有内置浏览器都能稳定播放。
