# 访问黑屏与手机加载修复

- 移除首页 CSS 对 Google Fonts 的外部 @import，改为同源 Kanit WOFF2，font-display: swap；保留 OFL 许可证。
- 三个项目详情按需导入，首屏 JS gzip 217.58 KB → 114.90 KB，首屏 CSS gzip 42.08 KB → 14.47 KB。
- About/Skills 帧序列改为进入该区域再请求；手机使用 18 张 640×360 JPG，解码内存约 15.82 MiB；原 54 张 1280×720 约 189.84 MiB。桌面保留原帧序列。
- 字体失败或超时不再阻止工牌图片与二维码生成。
- 增加不依赖脚本与样式文件的初始页面，以及运行时错误边界；资源失败时显示重新加载与邮件联系入口。
- 修正手机系统字体回退时首屏按钮被挤出边界的问题。

验证：本地构建；模拟所有字体 503 的手机/桌面页面；模拟入口脚本 503 的可见加载页；首屏请求不含动画帧或项目详情代码；滚动后仅请求手机 18 张帧图。字体失败测试环境首次内容绘制约 180 ms，此为本地测试，不能代表真实国内手机网络。

用户手机黑屏的完整网络追踪暂不可得；Google 字体阻塞与首屏内存压力是已发现并处理的风险，不应据此断言已复现用户设备上的唯一原因。

## 依据手机录屏追加的修复

- Hero 增加由原视频真实帧导出的透明静态封面（约 229 KB），预加载并优先显示；视频失败、低电量模式或尚未就绪时仍显示人物。
- 手机 About / Skills 使用单一正常文档流，取消重复图层和固定高度文字裁剪；动画只在有内容的紧凑横向画框内进行，保留已加载画面，最终图固定为 16:9。
- 手机卡片重新启用原生 sticky，逐层顶部偏移为 16 / 48 / 80px；移除 sticky 外层入场 transform，处理移动端媒体规则覆盖，Career 与 Projects 通过正常文档流相接。
- 原始大图保留，新生成 143 张屏幕展示 WebP：270.6 MB → 25.1 MB，单张最大约 514 KB。详情图上限 1600px 宽，长图上限 960px 宽，保留透明度。
- 32 个视频提供静态 WebP 封面，预览 preload=none，主项目封面按需加载，避免初始化争抢视频与大图下载。
- 最终首屏 JS gzip 118.08 KB，CSS gzip 14.91 KB。

确认：390/402px 手机视口下人物、About 文本与图片、Skills 横向终帧、叠放卡片；1280px 桌面保留原场景；项目详情按需导入成功；视频点击后 readyState=4；字体与 Hero 视频同时 503 时人物仍可见，联系工牌仍显示二维码。展示图 143 条与视频封面 32 条映射均校验文件存在。

手机与触屏设备的 Hero 默认使用静态人物，不请求方向跟随视频，也不注册桌面指针/滚轮跟随处理，避免争抢首屏带宽和滚动主线程。桌面精细指针保留原方向跟随。
